# 실험 기록

날짜순으로 쌓습니다. 실험마다 무엇을, 어떤 명령으로, 어디서 쟀는지 남겨서 다시 돌릴 수 있게 합니다.

## 2026-11-06 탐색 횟수 섞기 (playout cap randomization)

보드마당 [PR #32](https://github.com/shin1244/boardmadang/pull/32)의 `--fast-sims`. KataGo처럼 수의 25%만 깊게 탐색해서 학습 데이터로 남기고,
나머지는 얕게 탐색해 판을 진행하면 같은 시간에 더 나은 신경망이 나오는지 봤습니다.

- **게임**: `bench/games/c4-4x4` (중력 4목 4×4, 304,575국면, 완벽하게 두면 무승부)
- **예산**: 5분씩, 시드 1과 2. CPU 4코어 (클라우드 컨테이너, GPU 없음), 신경망은 기본 크기(4블록 × 64채널), 워커 4개
- **비교**: 반복마다 새 국면 수가 비슷하도록 섞는 쪽은 `--games`를 4배(400)로
- **채점**: `bench/grade.py`, 정답 국면 6만 개 (`bench/dump.mjs ... 60000`). 탐색 없이 신경망만

```bash
common="--minutes 5 --snapshot-every 0 --rollout-sims 0 --solve-limit 0 --eval-every 1000"
python boardmadang/trainer/train.py bench/games/c4-4x4 $common --seed 1 --out runs/puct-base-1
python boardmadang/trainer/train.py bench/games/c4-4x4 $common --seed 1 --fast-sims 10 --games 400 --out runs/puct-pcr-1
python boardmadang/trainer/train.py bench/games/c4-4x4 $common --seed 1 --search gumbel --sims 16 --out runs/gumbel-base-1
python boardmadang/trainer/train.py bench/games/c4-4x4 $common --seed 1 --search gumbel --sims 16 --fast-sims 4 --games 400 --out runs/gumbel-pcr-1
# 시드 2도 같게
python bench/grade.py runs/c4-4x4.bin runs/*/model.pt
```

`--fast-sims`는 PR #32로 보드마당에 들어갔고, submodule이 그 커밋(`d88b79d`) 이후를 가리킵니다.

가치를 늘 0이라고 답하면 오차가 0.359입니다 (정답 국면의 64.1%가 무승부). 마지막 평가에서 아무 수나 두는 상대에게는 8개 모두 한 판도 지지 않았습니다.

**결론**

- 섞으면 판 수는 3배쯤, 남긴 국면은 0.8배쯤이 됩니다.
- PUCT: 가치가 조금 나아지고(오차 평균 0.215 → 0.195), 정책은 조금 나빠집니다(92.5% → 91.2%). KataGo가 말한 방향과 같습니다.
- Gumbel: 셋 다 평균이 조금 나아지지만, 시드 1의 가치 오차는 오히려 나빠졌습니다.
- 같은 설정의 시드끼리 차이(PUCT 가치 오차 0.190~0.239)가 섞어서 생긴 차이보다 커서, **이 실험으로는 효과가 있다고 말할 수 없습니다.** 보드마당의 기본값은 꺼 둡니다.
- 따로 보인 것: 같은 5분이면 PUCT 50번이 Gumbel 16번보다 정책도 가치도 낫습니다. Gumbel은 판과 국면을 더 많이 만들고도 뒤집니다.

**다음에 잴 것**

- 한 판이 16수쯤이라 한 판의 국면끼리 닮아서 생기는 문제가 작은 게임이었습니다. KataGo는 한 판이 수백 수인 바둑에서 효과를 봤습니다.
  한 판이 길고 가치 학습이 약했던 Splat Chess(8×8, 한 판 20~30수)에서 GPU로 60분씩 다시 잽니다.
- 시드 간 차이가 크므로, 시드를 늘리거나 학습 시간을 늘려 차이가 굳는지 봅니다.

## 2026-11-06 스플체스 새 룰: 판 늘리기와 탐색 횟수 섞기 (12분)

스플체스 룰이 바뀌었습니다. 킹은 다른 기물을 따라 움직이지 않고 직접 8방향으로 움직이며, 움직이면 주변 9칸(3×3)을 칠합니다.
끝까지 가면 이기는 규칙은 없앴습니다. 내 기물도 상대 색에 둘러싸이면 잡히고, 나이트나 비숍을 골랐을 때 상대 색에 들어가 바로 잡히는 수가 있으면
붉은 `!`가 나옵니다. 새 룰로 처음부터 학습할 때
지난번 설정(1번)과, 판을 4배로 늘리고 탐색 횟수를 섞은 설정(2번)을 같은 12분으로 비교했습니다.

- **게임**: 보드마당 `games/private/splat-chess` (코드 버전 `932da09246be0c8c`, 8×8, 입력 27채널, 행동 64)
- **학습기**: 보드마당 `423d92e` (PR #33, `--init-from`, `--versus`, `--save-every`가 들어간 커밋)
- **기계**: Windows, RTX 2080 Ti, 물리 코어 4개, 워커 8개. 신경망 6블록 × 96채널
- **채점**: 정답을 모르는 게임이라 반복마다 찍는 "새 판" 손실(학습 전에 이번 반복의 자기대국으로 잰 것)의 마지막 20% 평균과, 두 모델끼리 200판

```bash
common="--minutes 12 --search gumbel --sims 16 --value-mix 0.5 --blocks 6 --filters 96 --snapshot-every 0 --rollout-sims 0 --eval-every 1000 --save-every 4 --seed 1"
python trainer/train.py games/private/splat-chess $common --games 256 --steps 100 --window 20 --out trainer/runs/p1-base
python trainer/train.py games/private/splat-chess $common --games 1024 --parallel 128 --fast-sims 4 --full-prob 0.25 --steps 150 --window 12 --out trainer/runs/p2-pcr
python trainer/train.py games/private/splat-chess --versus trainer/runs/p2-pcr/model.pt trainer/runs/p1-base/model.pt --eval-games 200 --sims 32 --seed 2
```

| | 1번 기준선 | 2번 판 늘리기 + 섞기 |
|---|---|---|
| 반복 / 판 | 38 / 9,728 (분당 796) | 26 / 26,624 (분당 2,163) |
| 새 판 정책 손실 | 1.599 | 1.464 |
| 새 판 가치 손실 (늘 0이라고 답하면) | 0.314 (0.346) | 0.312 (0.339) |
| 학습 데이터 가치 손실 | 0.066 | 0.158 |
| 아무 수나 두는 상대 | 40판 모두 이김 | 40판 모두 이김 |
| 서로 200판 (탐색 32번, 첫 2수 무작위) | | **2번이 58.5% (53.3~63.7%), Elo +60 (+23~+98)**. 82판이 되풀이 무승부로 끊김 |

워커 수: 2번 설정으로 3분씩 돌리면 워커 4개는 분당 약 1,900판, 8개는 약 2,240판이었습니다 (물리 코어 4개, 논리 코어 8개).

**결론**

- 2번이 정책도 낫고 1번을 이깁니다. 다만 시드 하나이고 두 가지(판 늘리기, 섞기)를 함께 바꿔서, 어느 쪽 덕인지는 모릅니다.
- **가치는 거의 배우지 못했습니다.** 새 판 가치 손실이 늘 0보다 조금 나은 정도인데, 학습 데이터에서는 1번이 0.066까지 내려갑니다.
  목표 칸 배치가 판마다 무작위라 배치가 판의 이름표가 되고, 한 판의 국면 30~40개가 같은 승패를 공유해서 판을 외웁니다.
  AlphaGo가 한 판에서 국면을 하나만 뽑은 이유와 같습니다 (참고: [references.md](references.md)의 학습 효율). 2번은 판이 많고 한 판에서 남기는 국면이 4분의 1이라 덜 외웁니다 (0.158).
- 모델끼리 두면 같은 판을 되풀이하다 끊기는 판이 많습니다 (200판 중 82판). 가치가 약해서 진전을 만들지 못하는 것으로 봅니다.
- **속도**의 병목은 워커 요청을 모아 GPU에 넣는 Python 프로세스 하나와 CPU 코어 수입니다. 반복마다 판을 늘려 요청 묶음을 키우면 Python 부담이 줄어서 판 수가 2.7배가 됐습니다.
- 3번(2번 설정 + 옛 룰 모델에서 `--init-from`)은 PC를 옮기느라 3번째 반복(2분)에서 멈췄습니다. 새 판 정책 손실이 2분 만에 1.469로 2번의 12분 끝과 비슷해서,
  정책은 옛 모델에서 시작하는 이득이 커 보입니다. 가치는 옛 룰 기준이라 처음엔 늘 0보다 나쁩니다 (0.334 대 0.287).
- `--versus`가 Windows에서 멈추는 버그를 찾았습니다 (모델 둘의 요청이 겹치면 파이프가 서로 기다림). 보드마당 `b936bdd`(PR #34)에서 고쳤고, submodule이 그 커밋을 가리킵니다.

**다음에 잴 것**

- 3번을 끝까지 돌려 2번과 대국. 이긴 쪽에서 이어 60분 학습해 사이트 모델로 올립니다 (새 게임 코드와 같은 때에).
- 가치 과적합을 줄일 것: 가치 손실 가중치 낮추기 (MuZero Reanalyze는 0.25), 좌우 대칭으로 데이터 늘리기, 칸마다 끝난 판의 색을 맞히는 보조 정답 (KataGo의 ownership).
- `--value-mix 0.8`, `--temp-moves 12~16` 비교.
- 학습기 속도: 자기대국과 학습을 동시에, 학습할 때 버퍼 전체를 매번 합치지 않기.

## 2026-11-07 공통 모델 첫 실험: 중력 N목 3개 함께 학습 (15분)

`madang/net.py`, `madang/train.py`로 신경망 하나가 벤치마크 게임 셋을 함께 배우게 하고, 게임마다 혼자 학습한 모델과 비교했습니다.

- **게임**: `c3-4x4`, `c4-4x4`, `c3-4x5`
- **학습기**: 혼자는 보드마당 `b936bdd`의 `train.py`, 함께는 `python -m madang.train`. 둘 다 4블록 × 64채널, 탐색 50번, 반복마다 게임당 100판
- **예산**: 혼자 5분씩, 함께 15분 (게임 셋). 시드 1과 2
- **기계**: Windows, RTX 3060 Ti, 12스레드, 워커 12개 (함께 학습은 게임마다 12개)
- **채점**: `bench/grade.py`. `c4-4x4`, `c3-4x5`는 정답 국면 6만 개, `c3-4x4`는 국면이 적어 둘 차례가 있는 44,913개 전부

```bash
common="--rollout-sims 0 --solve-limit 0"
python boardmadang/trainer/train.py bench/games/c3-4x4 --minutes 5 $common --snapshot-every 0 --eval-every 1000 --seed 1 --out runs/base-c3-4x4-1
python -m madang.train bench/games/c4-4x4 --minutes 5 $common --seed 1 --out runs/shared1-c4-4x4-1      # 구현 확인 (게임 하나)
python -m madang.train bench/games/c3-4x4 bench/games/c4-4x4 bench/games/c3-4x5 --minutes 15 $common --seed 1 --out runs/joint3-1
# 게임마다, 시드 2도 같게
python bench/grade.py runs/c3-4x4.bin runs/base-c3-4x4-*/model.pt runs/joint3-*/model.pt
```

**구현 확인**: 게임 하나(`c4-4x4`)만 주면 보드마당 학습기와 같은 점수가 나와야 합니다.

**결론**

- **구현은 결과를 바꾸지 않았습니다.** 게임 하나면 정책은 보드마당 학습기와 같고, 가치는 같거나 조금 낫습니다 (가운데 블록의 판 전체 풀링 덕일 수 있음).
- **`c4-4x4`는 함께 학습해도 혼자와 같습니다.**
- **`c3` 두 게임은 아직 판단할 수 없습니다.** 시드 1은 혼자와 비슷하거나 가치가 낫고, 시드 2는 정책과 가치가 모두 나쁩니다
  (`c3-4x5` 가치 오차 1.009로 늘 0보다 나쁨). plan.md 2단계의 "됐다"(시드 간 차이 안에서 혼자보다 나쁘지 않음)는 아직 아닙니다.
- **게임마다 계산이 같지 않았습니다.** 함께 학습의 한 반복은 세 게임을 다 두므로, 한 판이 긴 `c4-4x4`(평균 16수)가 시간을 더 쓰고
  `c3` 게임(7수)은 덜 씁니다. 그래서 반복 수가 `c4-4x4`는 혼자보다 많고(100 대 81), `c3` 게임은 27% 적습니다(100 대 137).
  `c3` 게임의 정책이 낮은 것은 이 탓일 수 있습니다.
- **`c3` 게임의 가치 오차는 시드마다 크게 흔들립니다.** 자기대국의 새 판에서 잰 가치 손실은 혼자든 함께든 끝에 0.05~0.11로 낮고 비슷합니다.
  `c3` 게임은 자기대국에서 선공이 98% 이기므로, 상대가 이상하게 둬서 후공이 이기는 국면은 거의 보지 못합니다. 채점의 가치 오차는 이런 국면에서 갈립니다.
  그래서 `c3` 게임의 가치 오차로 함께와 혼자를 가르려면 시드가 더 필요합니다.

**다음에 잴 것**

- 게임마다 계산 맞추기: 반복마다 게임별 국면 수가 같게 판 수를 정하거나, 게임별 반복 수를 혼자 학습과 같게 해서 비교
- 시드 3개 이상

## 2026-11-08 스플체스 가치 판 외우기 줄이기: 세 가지 설정 비교

스플체스는 새 판 가치 손실이 늘 0이라고 답하는 것보다 나쁩니다 (2026-11-06부터 계속).
한 판에서 나오는 국면 약 56개(수마다 고르기와 옮기기)가 모두 같은 승패를 정답으로 갖고, 판마다 무작위인 목표 칸 배치가 판의 이름표가 되어 승패를 외우는 것으로 봅니다.
이걸 줄이는 설정 셋을 스플체스 혼자 학습에서 비교했습니다.

- **탐색 평가 섞기** (`--value-mix 0.5`): 가치 정답을 최종 승패 반, 그 국면에서 탐색이 낸 평가 반으로 섞습니다. 국면마다 정답이 달라집니다. 원래 있던 옵션
- **가치 가중치 0.25** (`--value-weight 0.25`): 가치 손실을 4분의 1로 줄여 더합니다 (MuZero Reanalyze의 값). 이번에 새로 넣음
- **국면 4분의 1만 가치 학습** (`--value-keep 0.25`): 국면마다 무작위로 4분의 1만 가치를 배우고, 나머지는 정책만 배웁니다. 이번에 새로 넣음
- **조건**: 보드마당 학습기(`8763d9f`에 위 두 옵션을 더함. madang-ai 안의 `boardmadang` 사본에만 있고 커밋하지 않음), 4블록 × 64채널, 탐색 50번, 시드 6, 반복 41번. 셋을 함께 돌림 (1,447~1,551초)
- **기준**: `runs/splat-alone-s6` (같은 시드, 같은 반복 수, 옵션 없음. 2026-11-08 체스 기반 묶음 시드 6 실험의 혼자 모델)
- **처음 보는 판의 가치 오차**: 새로 만든 `madang/valuetest.py`로 쟀습니다. 한 모델이 학습 때처럼 자기대국 300판을 두고, 그 판의 모든 국면에서 각 모델의 가치를 실제 승패와 비교합니다.
  학습 로그의 "new games v"는 `--value-mix`를 쓰면 섞인 정답으로 재져서 비교가 안 되기 때문입니다.
  A는 `cont-chess2`(체스 기반 묶음 이어 학습 모델, 여기 넷과 다른 모델)가 둔 판, B는 기준 모델이 둔 판입니다

```bash
python boardmadang/trainer/train.py ../splat-chess --iterations 41 --minutes 900 --rollout-sims 200 --solve-limit 0 --snapshot-every 0 --eval-every 1000 --seed 6 --value-mix 0.5 --out runs/splat-vmix
python boardmadang/trainer/train.py ../splat-chess ... --value-weight 0.25 --out runs/splat-vw
python boardmadang/trainer/train.py ../splat-chess ... --value-keep 0.25 --out runs/splat-vkeep
python -m madang.versus ../splat-chess runs/splat-vmix/model.pt runs/splat-alone-s6/model.pt --games 200 --sims 50 --seed 6
python -m madang.valuetest ../splat-chess runs/cont-chess2/model.pt runs/splat-{alone-s6,vmix,vw,vkeep}/model.pt --games 300 --seed 99
python -m madang.valuetest ../splat-chess runs/splat-alone-s6/model.pt runs/splat-{alone-s6,vmix,vw,vkeep}/model.pt --games 300 --seed 98
```
