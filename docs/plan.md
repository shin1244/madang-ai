# 공통 모델 계획

여러 게임을 함께 배워서, 새 게임을 처음부터 배울 때보다 빨리 기초 수준에 이르는 모델을 만듭니다.
단계마다 "됐다"의 기준을 먼저 정하고, 벤치마크로 재서 넘어갑니다.

## 지금 가진 것

보드마당 학습기(`boardmadang/trainer`)가 이미 모든 게임을 같은 모양으로 바꿔 줍니다. 공통 모델은 이 위에 얹습니다.

**관측** (`env.js`의 `encode`, `[채널][rows][cols]`)

| 채널 | 개수 | 게임끼리 뜻이 같나 |
|---|---|---|
| 기물 | 게임마다 다름 (`xo` 2, `go-stones` 2, `chess` 12, 직접 정한 이름) | 아니요. 이름만 있고 누구의 기물인지 모름 |
| 표시 (`dot`, `ring`, `last-move`, `danger`, `ghost`, `blocked`, `frame`) | 7 | 예 |
| 칠한 칸 (선공 색, 후공 색, 그 밖) | 3 | 예 |
| 숫자 | 1 | 예 |
| 두는 쪽 (후공 차례면 1) | 1 | 예 |
| `observe()` | 게임마다 다름 | 아니요 |
| 판 안 (신경망이 붙임, 전부 1) | 1 | 예 |

뜻이 같은 13개 채널이 게임 사이의 공통 언어입니다. 기물과 `observe()` 채널만 게임마다 따로 받아 줘야 합니다.

**행동**: 칸 클릭 `rows × cols`개 + 특수 행동. 칸 클릭은 칸마다 점수를 내는 합성곱이라 모든 게임이 같은 머리를 쓸 수 있고, 특수 행동만 게임마다 따로입니다.

**내보내기**: 브라우저 AI는 `model.onnx`의 입력 `x[n, channels, rows, cols]`와 출력 `logits[n, nActions]`, `value[n]`만 봅니다.
공통 모델에서 게임 하나의 경로만 잘라 같은 모양으로 내보내면 사이트는 바뀌지 않습니다.

## 구조

```
게임별 입력층 (기물·observe 채널 → F)  ─┐
공통 입력층 (뜻이 같은 13채널 → F)      ─┴→ 더함 → 공통 몸통 (잔차 블록 + 판 전체 풀링) → 칸 클릭 머리 (공통)
                                                  ↑ 블록마다 게임 벡터로 크기·치우침 조절 (FiLM)   → 가치 머리 (공통)
                                                                                                → 특수 행동 머리 (게임별)
```

- **게임 벡터**: 게임마다 작은 벡터(16~32차원)를 두고, 공통 층이 이걸 블록마다의 크기와 치우침으로 바꿉니다.
  같은 모양의 판이 게임마다 다른 뜻일 때(예: 줄을 만들면 지는 게임) 모델이 지금 어떤 게임인지 알게 합니다.
- **판 전체 풀링**: 몸통 중간에 판 전체를 평균·최댓값으로 모아 칸마다 더해 줍니다 (KataGo). "33칸을 먼저 칠하면 승리"처럼 판 전체를 세는 규칙을 위해서입니다.
- **판 크기가 섞임**: 완전 합성곱이라 크기와 상관없습니다. 한 묶음(batch)에는 한 게임만 넣고, 학습 한 걸음에 여러 게임의 묶음을 모아 같이 갱신합니다.
- **정규화의 평균·분산은 게임마다 따로**: 한 묶음에 한 게임만 들어가므로, 배치 정규화의 평균·분산을 같이 재면 평가 때 쓰는 값이
  마지막에 본 게임 쪽으로 쏠립니다. 그래서 평균·분산만 게임마다 따로 두고, 크기·치우침은 게임 벡터에서 냅니다.
  모든 층의 크기·치우침은 게임 벡터에서 한 번에 계산합니다. 층마다 따로 하면 작은 판에서는 신경망 한 번이 두 배 넘게 느려졌습니다.
- **크기**: 지금 게임별 모델은 4블록 × 64채널입니다. 공통 몸통은 6블록 × 96채널에서 시작하고, 브라우저에서 느리면 게임별 작은 모델로 줄입니다 (4단계).

## 단계

### 0단계: 재는 도구와 기준선

탐색 횟수 섞기 실험에서 시드 두 개의 차이가 비교하려던 차이보다 컸습니다. 그래서 먼저 재는 방법을 단단히 합니다.

- **벤치마크 게임 늘리기**: 지금은 중력 N목 3개뿐입니다. 서로 닮은 게임, 덜 닮은 게임, 반대인 게임이 있어야 전이를 잴 수 있습니다.

  | 묶음 | 게임 | 재려는 것 |
  |---|---|---|
  | 닮은 것 | 중력 N목 크기·N 여러 개, 놓기 N목 (중력 없음) | 가까운 게임으로 옮길 때 |
  | 덜 닮은 것 | 작은 오델로, 작은 Breakthrough (이동), 작은 땅따먹기 | 먼 게임으로 옮길 때 |
  | 반대인 것 | 미제르 3목 (줄을 만들면 짐) | 같은 모양이 반대 뜻일 때 망가지지 않는지 |

  완전 탐색이 되는 크기는 정답으로 채점하고, 안 되는 크기는 고정한 상대(롤아웃 AI, 처음부터 학습한 모델)와 양쪽 차례로 200판 이상 둬서 잽니다.
- **보드마당 학습기에 작은 기능 셋** (보드마당에도 쓸모가 있어 그쪽 PR로. [PR #33](https://github.com/shin1244/boardmadang/pull/33)으로 들어감)
  - `--init-from <model.pt>`: 다른 모델에서 시작. 모양이 같은 층만 옮기고, 입력층과 특수 행동 머리는 다르면 새로 만듭니다. 게임 새 버전을 다시 학습할 때 바로 씁니다.
  - `--save-every <분>`: 중간 모델을 남겨 시간에 따른 곡선을 그립니다.
  - 모델 대 모델 대국: 두 신경망을 서로 두게 합니다. 정답을 모르는 게임의 채점과 난이도 단계 비교에 씁니다.
- **기준선**: 벤치마크 게임마다 처음부터 학습한 곡선 (시드 3개, 2·5·10분). 이후 모든 비교의 잣대입니다.
- **됐다**: 같은 설정을 시드만 바꿔 돌렸을 때의 차이를 게임마다 압니다 (이보다 작은 차이는 효과로 치지 않음).

### 1단계: 이어 학습 (게임 둘 사이)

- 게임 A로 학습한 모델에서 B를 시작해, 처음부터 학습한 B와 같은 시간으로 비교합니다. 닮은 쌍, 먼 쌍, 반대인 쌍을 다 잽니다.
- 같은 게임의 새 버전은 이 단계에서 바로 쓸 수 있습니다 (`--init-from`).
- **됐다**: 닮은 쌍에서 기준선의 5분 점수에 절반 이하의 시간으로 이릅니다. 먼 쌍과 반대인 쌍은 몇 분 안에 처음부터 학습한 것을 따라잡습니다 (손해가 남지 않음).

### 2단계: 함께 학습

- 위 구조로 벤치마크 게임 여러 개를 동시에 학습합니다. 게임마다 자기대국 워커 묶음을 따로 띄우고(보드마당의 `Worker`, `Pool`을 그대로 씀), 신경망만 공유합니다.
  게임마다 학습 데이터를 따로 쌓고, 학습할 때는 게임마다 같은 양을 뽑습니다 (한 게임이 모델을 차지하지 않게).
- 게임 하나만 넣으면 처음부터 학습한 기준선과 같은 점수가 나오는지 먼저 확인합니다 (구현이 결과를 바꾸지 않았는지).
- **공통 모델은 두 묶음으로 나눕니다** (2026-11-07 결정).
  - 바둑 기반: 빈칸에 돌을 놓는 게임. N목, 오델로, 바둑, 개척 오목.
  - 체스 기반: 판 위의 기물을 옮기는 게임. 스플체스, 작은 Breakthrough 등.
  - 스플체스를 바둑 기반 모델에 붙였더니 같은 반복 수로 혼자 배운 모델보다 약했습니다 (44.8%, Elo −37. [experiments.md](experiments.md)).
  - 체스 기반 묶음: 스플체스, `bench/games/shogi-3x4` (십이장기 규칙). 체스960도 만들어 봤지만 아무렇게나 두면 한 판이 300수쯤이라 학습이 너무 느려 뺐습니다.
    첫 실험(2026-11-08, 처음부터 2시간, 시드 둘): 같은 반복 수에서 스플체스는 혼자와 비슷하고 십이장기는 혼자보다 조금 약했습니다 (두 시드 합쳐 스플체스 48.2%, 십이장기 44.9%. [experiments.md](experiments.md)).
    2시간 더 이어 학습하니 십이장기는 크게 강해졌고 (전 모델 상대 79.5%, Elo +235) 스플체스는 그대로였습니다 (49.5%). 스플체스는 가치를 못 배우는 것(판 외우기)이 먼저 풀 문제입니다.
    스플체스 가치 판 외우기는 가치 정답에 탐색 평가를 반 섞으면(`--value-mix 0.5`) 풀렸습니다. 처음 보는 판 가치 오차가 처음으로 늘 0보다 낮아졌고, 두 시드 모두 기준을 이겼습니다 (합쳐서 56.5%, Elo +45).
    공통 모델(체스 기반 묶음)에서도 섞기가 섞기 없는 묶음을 이겼습니다 (스플체스 +83, 십이장기 +158). 다만 섞기를 둘 다 켜도 묶음은 혼자보다 조금 약합니다 (−12, −33). 개척 오목, 십이장기도 혼자 학습에서 섞기로 크게 강해졌습니다 (+424, +217~+275).
- **새 게임 붙이기**: 학습에 안 넣은 게임 하나를 남겨 두고, 몸통은 얼린 채 입력층·특수 행동 머리·게임 벡터만 몇 분 학습합니다. 그다음 필요하면 전체를 짧게 이어 학습합니다.
- **됐다**: 함께 학습한 모델이 게임마다 같은 계산을 쓴 단독 모델보다 나쁘지 않고 (시드 간 차이 안), 남겨 둔 게임에서 1단계의 이어 학습보다 빨리 기준선 점수에 이릅니다.

### 3단계: 학습 없이 바로, 그리고 내보내기

- **게임 하나 잘라 내보내기**: 공통 모델에서 그 게임의 입력층·게임 벡터·머리만 붙인 경로를 지금과 같은 `model.onnx`, `model.json`으로 내보냅니다. 사이트의 AI 대국에서 그대로 도는지 확인합니다.
- **규칙 지문**: 새 게임을 무작위로 몇백 판 둬 보며 특징을 잽니다. 한 판의 길이, 둘 수 있는 수의 개수, 기물이 사라지는지(잡기), 기물이 움직이는지(이동)
  또는 놓이기만 하는지(놓기), 끝날 때 판이 얼마나 차는지, 어떤 표시와 칠하기를 쓰는지. 이 지문으로 게임 벡터를 짐작하면 학습 없이도 바로 둘 수 있습니다.
  제작자에게 새 함수를 요구하지 않고 게임을 돌려서만 얻습니다 (원칙 1).
- **기물 역할 알아내기**: 지금 기물 채널은 이름뿐이라 게임별 입력층이 따로 필요합니다. 선공이 둘 때 어떤 기물이 생기고 움직이는지 보면 "내 기물·상대 기물"을 알아낼 수 있고,
  그러면 입력층도 공유할 수 있습니다.
- **줄이기 (증류)**: 공통 모델이 브라우저(WASM)에서 느리면, 게임마다 지금 크기(4×64)의 작은 모델이 공통 모델을 흉내 내도록 학습해서 내보냅니다.
- **됐다**: 남겨 둔 게임에서 학습 없이 아무 수나 두는 상대를 확실히 이기고, 몇 분 붙이면 기준선의 10분 점수에 이릅니다.

### 4단계: 실제 게임

- **먼저 본인이 만든 게임**(틱택토, Cellmoku, Splat Chess): 다른 사람의 허락이 필요 없습니다. 게임 폴더는 운영자 화면의 "코드 받기" zip이나 로컬 폴더에서 가져옵니다.
  공개 레포에 넣지 않을 게임은 `games/private/`처럼 git에 안 올라가는 폴더에 둡니다.
- **다른 제작자의 게임**: 약관과 "AI 만들기" 동의 창에 공통 모델 용도를 밝힌 뒤에만 넣습니다 (README의 "시작하기 전에 정할 것").
- **격리**: 게임 코드를 돌리는 Node 워커는 네트워크가 없고 읽기 전용인 컨테이너에서 돌립니다. 신경망(PyTorch)은 밖에서 돌고 표준 입출력으로만 이야기합니다.
- **데이터 저장소**: 게임 id와 코드 버전별로 쌓고, 내린 게임은 다음 학습부터 뺍니다. 게임마다 양에 상한을 둡니다.
- **오염 막기**: 새 게임을 함께 학습에 넣기 전과 뒤에 다른 게임들의 벤치마크 점수를 재서, 떨어지면 넣지 않습니다.
- **됐다**: 실제 게임 하나가 사이트에서 공통 모델로 학습한 AI를 쓰고, 처음부터 60분 학습한 AI 이상으로 둡니다.

## 어디서 돌리나

| 일 | 어디서 | 까닭 |
|---|---|---|
| 벤치마크 실험 (작은 판, 몇 분씩) | 클라우드 세션 (CPU 4코어) | 정답이 있는 작은 게임은 CPU로 충분하고, 결과를 바로 레포에 기록 |
| 실제 게임, 큰 모델 | 개인 PC (GPU) | 큰 판과 6×96 이상의 몸통은 GPU가 필요 |

## 코드 위치

| 무엇 | 어디 |
|---|---|
| 공통 신경망 (게임별 입력층, 게임 벡터, 공통 몸통, 머리) | `madang/net.py` |
| 여러 게임을 함께 학습 (게임마다 워커 묶음, 게임별 데이터, 균형 잡힌 학습) | `madang/train.py` |
| 게임 하나 잘라 내보내기 | `madang/export.py` |
| 규칙 지문 | `madang/fingerprint.mjs` |
| 벤치마크 게임, 채점, 곡선, 모델 대 모델 | `bench/` |
| 이어 학습, 중간 모델 저장, 모델 대 모델 대국 | 보드마당 `trainer/` ([PR #33](https://github.com/shin1244/boardmadang/pull/33)) |

관측 인코딩과 탐색은 보드마당 것을 그대로 불러 씁니다. 여기서 고쳐 쓰지 않습니다 (브라우저와 어긋나지 않게).

## 위험과 대응

| 위험 | 대응 |
|---|---|
| 재는 값이 시드마다 흔들림 | 시드 3개 이상, 한 점 대신 곡선, 시드 간 차이보다 작은 차이는 효과로 치지 않음 |
| 서로 다른 게임이 서로 방해함 | 게임 벡터와 게임별 입력층, 반대인 게임(미제르)으로 확인, 너무 먼 게임은 묶음을 나눔 |
| 새 게임을 배우면 옛 게임을 잊음 | 모든 게임의 데이터를 계속 섞어 학습 |
